# 货代业务工作流设计

本文定义 ZungMail 里"一票货"相关的领域概念与判定规则。规则都落在 Core 的纯函数里，可单测、可复查。

## 1. 作业链路与断点

货代邮件作业大致沿这条链路走：

```
询价/报价 → 订舱（Booking / SO）→ 放舱确认 → 装箱/拖车 → 报关 → 截关/截单
        → 开船（ETD）→ 提单确认（B/L 草稿 → 正本/电放）→ 到港（ETA）→ 费用结算 → 归档
```

真正会"漏单 / 错单 / 延误"的断点集中在五处，也是本产品要解决的：

| 断点 | 表现 | 产品应对 |
|---|---|---|
| 单号散落在主题与正文里 | 换个文件夹就找不到同一票货 | 自动抽取业务单号并跨文件夹聚合 |
| 节点靠人记 | 截关/截补料/VGM 到期没人提醒 | 时效节点看板 + 倒计时 |
| 催办靠翻邮件 | 发了报价没人回，一拖三天 | 等待回复 + 到点提醒 |
| 同类邮件混在一起 | 订舱确认、SI、账单、查验看不出区别 | 行业邮件类型识别与角标 |
| 换人接手 | 上下文散在几十封邮件里 | 一票货案件页（时间轴 + 附件 + 资料包） |

## 2. 一票货（Shipment Case）

- **定义**：以一组业务单号为键聚合出来的邮件集合；一个案件有标题、状态、时间轴、参与方与附件清单。
- **归集**：邮件入库时抽取单号 → 命中已存在案件就追加，否则按主单号新建。
- **跨账户**：同一票货可能同时出现在操作、订舱、财务不同邮箱里，案件不按账户隔离。
- **导出**：案件可导出资料包（邮件 + 附件清单），用于交接与留档。

## 3. 业务单号

抽取顺序与优先级（高 → 低）：

| 类型 | 典型形态 | 说明 |
|---|---|---|
| Job No.（内部作业号） | `JOB1234567`、`SZ240001` | 优先级最高，命中即作为案件主键 |
| 订舱号 / SO | `SO1234567`、`BKG…` | 订舱阶段的锚点 |
| 提单号 B/L | `HBL…`、`MBL…`、`SHZ…` | 分 House / Master，两者都记 |
| 箱号 | 4 位字母 + 7 位数字（含校验位） | 校验位算法单独实现，误报率低 |
| 封号 | `CN…`、`SEAL…` | 常与箱号同现 |
| 发票号 / PO | `INV…`、`PO…` | 结算阶段 |
| 空运单 | 3 位航司代码 + 8 位序号 | 空运场景 |
| 船名航次 / 港口 | `VSL/VOY`、`CNSHA` / `NLRTM` | 作为结构化辅助字段，不单独成案件 |

规则：

- 正则**只在邮件头与正文的有效文本里跑**，先做 HTML 去标签与断行归一，避免把签名里的号码误当单号。
- 同一类型出现多次时取"最像"的一条（长度、校验位、上下文关键词），其余作为候选保留。
- 校验位不通过的箱号不入索引（宁可漏，不可错）。
- 索引是增量补扫的：新装/升级后后台补扫历史邮件，界面上标"待补扫 N 封"。

搜索运算符与之一一对应：`job:`、`booking:` / `so:`、`bl:`、`ctr:`、`seal:`、`inv:`、`po:`、`awb:`、`ref:`（任意类型）。

## 4. 行业邮件类型

按主题优先、正文补充的顺序判定，命中即打角标：

订舱确认、SI（补料）、VGM、提单草稿 / 提单确认、到货通知（AN）、账单 / 费用、查验、甩柜 / 退关、延误 / 改配、报价。

- 异常类型（查验、甩柜、延误、改配）在列表上红色高亮，其余用中性色。
- 类型可关闭（设置 → 货代 → 邮件类型），关闭后不再识别也不再显示角标，历史数据保留。
- 搜索 `type:si` 这类运算符按类型过滤。

## 5. 时效节点

抽取四类关键时间，并生成倒计时卡片：

| 节点 | 典型表述 | 提醒 |
|---|---|---|
| 截关 / 截港（Closing） | "截关 10/24 17:00"、"截港 Friday noon" | 提前提醒 + 超时标红 |
| 截补料（SI Cut-off） | "SI cut-off"、"补料截止" | 提前提醒 |
| VGM 截止 | "VGM cut-off" | 提前提醒 |
| ETD / ETA | "ETD 11/02"、"ETA Dec 5" | 展示与倒计时 |

- 时间按邮件里的时区/无时区分别处理，无时区时按本机时区解释并在卡片上标注。
- 时效节点只看**最近往来**的邮件，历史同线程的旧节点归档，不重复提醒。
- 节点到期只提醒一次，不追着弹。

## 6. 等待回复（Follow-up）

- 登记时选择：等谁回（收件人/抄送/全部）、最少回复人数、下次检查时间。
- 到点检查该线程是否收到符合条件的新邮件；满足即自动结束，否则托盘提醒一次。
- 支持"+4 小时"稍后与本机备忘；催信只能由用户手动发起，产品不代发邮件。

## 7. 数据与隐私边界

- 单号、类型、时效都是**本地索引**，不上传服务器；案件与资料包也只在本机。
- 识别结果不做"云查"：不查询外部威胁情报、不做 DNS/证书验证。
- 关闭货代功能只影响后续识别与入口显示，既有数据保留；重新开启后自动补扫。

## 8. 验收要点

- 一票货：同一单号的邮件跨文件夹、跨账户能在案件页聚齐；案件导出含全部附件。
- 单号：合法箱号不误判、带校验位错误的不入索引；主题里只有部分单号时仍能命中主单号。
- 时效：截图里的"截关 10/24 17:00"能在看板看到倒计时并按时提醒。
- 跟进：登记后到点只提醒一次；对方回复后自动结束。
- 搜索：`booking:` / `bl:` / `ctr:` / `type:` 与手写语法结果一致。
